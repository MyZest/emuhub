## 目标
- 在 `android-docker/common/tools/start-device-session.sh` 中按传入的 `API` 自动定位容器内的 Android 版本资源根目录，并执行与 Dockerfile 等效的复制与权限设置：将对应版本的 `tools` 复制到 `/opt/tools`、`licenses` 复制到 `/opt/licenses`，同步 `android-env.sh` 到 `/opt/android-sdk-linux/bin/`，随后继续现有会话启动流程。

## 现状与依据
- 会话脚本当前位置：`android-docker/common/tools/start-device-session.sh`，加载 `android-env.sh` 与工具目录，未进行版本资源复制与容器路径校准（见 android-docker/common/tools/start-device-session.sh:25-31）。
- Docker 镜像构建阶段已有静态复制：`COPY android-docker/common/tools /opt/tools`、`COPY android-docker/android34/tools /opt/tools`、`COPY android-docker/android34/licenses /opt/licenses`（见 Dockerfile:43-50）。
- Web 端版本探测与路径候选：`process.env.ANDROID_DOCKER_DIR`、`'/opt/android-docker'`、`path.join(process.cwd(), 'android-docker')`、`'/opt/app/android-docker'`（见 web/pages/api/devices/[id]/start.js:12-18），会话脚本应复用一致的候选策略以“校准容器路径”。
- `android-env.sh` 已按版本提供在 `android-docker/android{API}/tools/android-env.sh`，并在 SDK 更新脚本中复制到 `bin`（见 android-docker/android34/tools/android-sdk-update.sh:3-5,47-52）。现需在会话启动时确保该复制与版本对应。

## 修改方案
1. 解析容器资源根目录
- 在会话脚本最前加入容器路径解析：按以下候选顺序取第一个存在的目录作为 `ANDROID_DOCKER_DIR`：
  - `$ANDROID_DOCKER_DIR`
  - `'/opt/android-docker'`
  - `'/opt/app/android-docker'`
  - `"$(pwd)/android-docker"`
- 若均不存在，记录警告日志并跳过复制，保持现有行为。

2. 按 API 选择版本目录
- 目标目录：`"${ANDROID_DOCKER_DIR}/android${API}"`
- 校验该目录存在；若不存在可回退到当前已存在的 `/opt/tools` 与 `/opt/licenses`（并在日志中标注），不阻断会话。

3. 执行等效 Dockerfile 的复制与权限设置
- 将 `"${ANDROID_DOCKER_DIR}/android${API}/tools"` 复制到 `/opt/tools`（覆盖同名文件）。
- 将 `"${ANDROID_DOCKER_DIR}/android${API}/licenses"` 复制到 `/opt/licenses`（覆盖同名文件）。
- 执行权限：
  - `find /opt/tools -type f -name "*.sh" -exec chmod +x {} \;`
  - `chmod -R 0755 /opt/tools /opt/licenses`

4. 同步 SDK bin 并加载环境
- 将 `/opt/tools/android-env.sh` 复制到 `/opt/android-sdk-linux/bin/android-env.sh`（确保最新版本生效）。
- 若文件存在，立即 `source /opt/android-sdk-linux/bin/android-env.sh`；随后继续脚本原有流程（系统镜像检查、Xvfb/VNC/WebSocket、模拟器启动）。

5. 幂等与安全
- 所有复制操作均可重复执行且不破坏会话；失败时只记录日志并保留现有 `/opt/tools`、`/opt/licenses`。
- 不修改 Web 端 API 逻辑；仅在会话启动端进行路径校准与版本落盘，使任意 `API` 启动都能使用对应版本的工具与许可。

## 验证方案
- 在容器或开发环境内放置两个版本（如 `android32` 与 `android34`）的 `tools/licenses` 目录。
- 通过 Web API 启动设备：`/api/devices/:id/start`，分别传入 `api=32` 与 `api=34`，确认：
  - `/opt/android-sdk-linux/bin/android-env.sh` 内容随 `API` 变化。
  - `/opt/tools` 下脚本权限正常，可执行。
  - 会话成功启动，日志包含复制与权限设置信息。
