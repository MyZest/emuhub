## 目标
- 不使用 WebSocket/实时流；提供“刷新查看”的日志展示。
- 点击“Start”后接口返回设备 `id`，前端跳转到对应页面，用户可手动/定时刷新查看日志。

## 后端
- 新增 REST 接口：`GET /api/devices/[id]/logs`
  - 入参：`files=session,x11vnc,emulator,websockify,xvfb`（默认全选），`tail=200`（返回最后 N 行）。
  - 路径映射：`/var/log/emuhub/d${id}/<name>.log`（白名单映射，禁止任意路径）。
  - 返回：JSON，按文件分组，如：
    ```json
    {
      "session": ["...", "..."],
      "x11vnc": ["..."],
      "emulator": ["..."]
    }
    ```
  - 行数与大小限制：N 行总大小上限（如 1MB），避免过大响应。
- 可选：`GET /api/devices/[id]/logs/meta` 返回可用日志文件列表、最新更新时间等。

## 前端
- 页面：`web/pages/devices/[id].jsx` 增加“日志”面板或 `tab=logs`。
- 行为：
  - 进入页面或点击“刷新”按钮时调用 `GET /api/devices/${id}/logs?tail=200`。
  - 展示按来源（`session/x11vnc/emulator/...`）分组的日志，支持：清屏、复制、关键字过滤（前端过滤）。
  - 可选开启“自动刷新”（如每 5–10 秒一次）开关，默认关闭。
- 跳转：
  - 在“Start”操作成功后（调用 `web/pages/api/devices/[id]/start.js`），从响应中获取 `id`，前端跳转到 `/devices/${id}?tab=logs`。

## 安全与鲁棒性
- 文件名使用白名单，避免路径遍历。
- 对 `tail` 设置上限（如 ≤2000）；响应体大小限制。
- 文件不存在时返回空数组并在 UI 提示“暂无日志”。

## 验证
- 启动设备会话，确认 `d${id}` 目录生成各日志文件。
- 打开设备详情页“日志”，点击“刷新”看到最后 N 行；写入新日志后再次刷新可见最新内容。
- 测试文件不存在、超大日志、自动刷新启停等情况。
