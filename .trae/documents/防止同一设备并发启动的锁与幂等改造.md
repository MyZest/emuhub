## 现状与并发影响
- 服务端端口已按设备 ID 分配：`display=":"+(10+did)`、`vnc=5900+did`、`ws=6080+did`（web/pages/api/devices/[id]/start.js:70–72），不同设备并发安全。
- 会话脚本使用锁文件但未阻断并发：检测到锁仅记录日志后继续执行（android-docker/common/tools/start-device-session.sh:31–35）。若同一设备在同一秒多次点击 start，将出现重复启动竞态，可能造成 AVD 创建与 emulator 进程冲突。
- 系统镜像安装路径已按 API 分层，安装阶段存在并发竞态（两个会话同时安装同一 API 镜像）。

## 修正方案（最小改动）
1. 设备级互斥锁
- 在 `start-device-session.sh` 对 `LOCK_FILE=/tmp/emu_session_${DID}.lock` 使用 `flock -n` 获取独占锁；获取失败则直接退出并记录“already starting”。
- 在关键步骤（镜像安装、Xvfb/x11vnc/websockify、AVD 检查与 emulator 启动）处于锁保护下，确保同一 DID 单进程执行。

2. 系统镜像安装互斥
- 以 API 为维度增加安装锁：`/tmp/sdk_sys_android_${API}.lock`，在执行 `sdkmanager "${SYS_IMG}"` 前用 `flock -n` 获取锁；获取失败说明另一会话正在安装，当前会话等待或直接跳过并检查目录存在。

3. 幂等与早退出
- 若检测到 `pgrep -f "emulator.*-avd ${AVD_NAME}"` 已存在，直接退出（而不是继续启动）。
- 端口分配仍使用设备固定端口，保持稳定；无需在并发场景下争抢端口。

## 验证
- 同一设备 ID 在同一时刻触发两次 start：第二次立即收到“already starting”，只保留一个 emulator 实例。
- 两个设备同时首次使用同一 API：镜像只安装一次；另一会话在镜像可用后正常启动。

## 改动范围
- 修改 `android-docker/common/tools/start-device-session.sh`：添加 `flock` 锁逻辑与早退出；将镜像安装放入 API 级锁。
- 无需修改 Web 端 `start.js`。
