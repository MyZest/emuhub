## 难度评估
- 综合难度：中等偏高（实时投屏与双向控制、多端网络适配、服务部署约束）。
- 主要复杂度来源：实时屏幕图像渲染与回压、触控/键盘事件注入、局域网设备发现与连接管理、服务端环境（无 UDP/无长连接）限制、权限与安全治理。
- 法律与合规：不支持“盗取界面”。可在遵守开源许可前提下，复刻类似交互与视觉效果，避免复制受版权保护的素材与品牌元素。

## 法律与合规
- 尊重开源许可与版权：仅复刻交互逻辑与布局结构，UI 视觉与素材由你方原创设计；若引用代码需遵循仓库许可并保留署名。
- 不复制第三方受保护资产：图标、Logo、文案、配色体系需重新设计或使用可商用素材库。

## 集成方案
- 浏览器直连模式：在 Next.js 客户端使用 `android-bot` 的 `Device` 与 `BrowserWebSocket`，通过设备 IP:Port 直连，获取实时屏幕 JPG 流并发送触控/键盘事件。适合同局域网、无需服务端 UDP 的场景。
- 服务端桥接模式：在 Next.js 的 Node 运行时使用 `NodeWebSocket` 与 `AdbDevice.listWifiDevices()`进行局域网设备发现与会话管理，通过 API 路由或自建网关转发事件与图像流；适合需要统一权限控制、记录审计或跨网访问。注意：部分托管环境不支持 UDP/长连接，建议自托管或独立 Node 服务。

## 关键模块
- 设备列表与连接
  - 列表页：展示可用设备（浏览器模式手动输入 IP，服务端模式自动发现）。
  - 连接态管理：连接、断开、心跳、异常重连。
- 投屏与控制面板
  - 屏幕渲染：Canvas/Img 帧驱动渲染，帧率控制与回压（避免内存暴涨）。
  - 触控注入：单指/多指手势、拖拽、缩放；键盘输入；剪贴板读写。
  - UI 层：工具栏（暂停/继续、录制、截屏）、缩放、旋转适配、性能统计。
- 功能页
  - 文件管理：上传/查询/删除。
  - 应用管理：安装/卸载/启动/停止/清数据。
  - 屏幕布局：JSON/XML 解析与元素探查。
  - 通讯录、通知监听、短信查询等按需启用。
- 会话与权限
  - 用户鉴权与设备授权；操作审计日志；速率限制与黑名单。
- 错误处理与健壮性
  - 连接断开重试、队列溢出防护、异常上报与告警。

## Next.js 兼容要点
- App Router：客户端组件承载实时 UI；服务端 Route Handler 提供桥接 API（如采用服务端桥接模式）。
- 客户端运行时：直接使用浏览器原生 WebSocket 与 `Device`；不依赖 UDP 扫描。
- 服务端运行时：需 Node 长连与 UDP 能力；若托管平台不支持，迁移到自托管或独立 Node 进程。
- 状态管理：以轻量状态库管理连接态、设备信息、帧队列与控制命令。
- 性能优化：批处理事件、限速、丢帧策略、WebWorker/OffscreenCanvas（可选）。

## 风险与限制
- 局域网限制：浏览器直连需设备 IP 可达；跨网需桥接或隧道。
- 部署环境：Serverless 平台常限制 WebSocket/UDP；需自托管或独立网关。
- 安全与合规：严格的权限控制与操作审计，防止越权与滥用。
- 设备兼容：不同 Android 设备的旋转/分辨率/输入行为差异需适配。

## 视觉与交互复刻策略
- 交互等效：保留核心操作流（设备选择→连接→投屏→控制→工具页），不复制受保护视觉资产。
- 设计落地：建立你方独立设计语言（色板、字体、组件规范），确保长期可维护与品牌一致性。

## 验收要点
- 实时渲染稳定（目标帧率、内存占用、断线重连）。
- 触控与键盘事件响应正确（单/多指、中文输入）。
- 文件/应用/剪贴板/布局等功能按需打通，具备权限与审计。
- 兼容 Next.js 运行与部署约束，明确环境差异与回退方案。
