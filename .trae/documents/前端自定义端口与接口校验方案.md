## 目标
- 仅在前端提供一个“ADB 端口”输入框；VNC 与 WebSocket 端口按 ADB 端口递增（分别 +1、+2）。
- 启动前做接口校验：任一端口占用则提示用户更换端口并阻止启动。

## 前端改动
- 文件：`web/pages/devices/[id].jsx:108-160`
- UI：新增数值输入框 `ADB 端口`（默认值建议 `5555`）。
- 计算规则：
  - `vnc_port = adb_port + 1`
  - `ws_port = adb_port + 2`
- 校验：
  - 范围 1024–65535；三者互不冲突。
  - 在失焦与点击“Start”前调用端口校验接口。
- 请求：`POST /api/devices/{id}/start` 的 `body` 仅传 `adb_port`；服务端据此推导 `vnc/ws`。

## 后端改动
- 新增端口校验接口：`web/pages/api/ports/check.js`
  - 入参：`adb`, （服务端推导出 `vnc=adb+1`, `ws=adb+2` 进行检测），或支持传 `vnc/ws` 直接校验。
  - 实现：使用 `net` 连接 `127.0.0.1:<port>`，在 300ms 超时内判定是否监听；返回 `{ ok: true, adb:{inUse}, vnc:{inUse}, ws:{inUse} }`。
- 启动接口：更新 `web/pages/api/devices/[id]/start.js`
  - 读取 `adb_port`；做范围校验。
  - 推导 `vnc_port = adb_port + 1`、`ws_port = adb_port + 2`。
  - 端口占用校验：任一占用则返回 `409 { ok:false, error:'port in use', details:{adb|vnc|ws} }`。
  - `DISPLAY` 与会话映射：用 `seed = (adb_port % 1000)`，`DISPLAY=":" + (10 + seed)`（保持与现有方案一致）。
  - 将端口写入启动参数：仍按脚本的第 3、4 个参数分别传 `VNC_PORT`、`WS_PORT`。
  - 传递环境变量：在 Node `spawn` 中加入 `env`，注入：
    - `EMU_ADB_PORT=adb_port`
    - `EMU_CONSOLE_PORT=adb_port-1`
- 运行脚本：`android-docker/common/tools/run-emulator-with-profile.sh`
  - 读取上述环境变量，若存在则附加 emulator 参数：
    - `-ports ${EMU_CONSOLE_PORT},${EMU_ADB_PORT}`

## 兼容性与注意事项
- 当前 `start-device-session.sh` 会在端口被占用时自动选择空闲端口（`start-device-session.sh:59-87`）；为满足“占用即提示更换”，我们在服务端提前拦截并返回 `409`。极端情况下校验与实际启动之间端口被占用，脚本仍可能递增到空闲端口，导致与用户选择不一致；此行为可在后续迭代中移除递增以完全一致。
- ADB 端口与 Console 端口的标准关系：console = adb - 1；通过 `-ports` 显式设置更稳妥（`run-emulator-with-profile.sh:31-37` 将新增该参数）。

## 验收
- 前端仅填 ADB 端口即可；UI显示推导出的 `VNC/WS` 值；校验接口若提示占用则阻止启动。
- 启动成功后，返回的 `device.vnc/ws` 分别等于 `adb+1/adb+2`；日志可按时间戳 `id` 读取。
- 在 emulator 进程中可见 `-ports console,adb` 按用户输入生效。
