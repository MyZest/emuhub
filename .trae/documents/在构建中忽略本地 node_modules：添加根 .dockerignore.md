## 目标
- 在 Docker 构建时排除本地依赖与开发产物（node_modules、.next、dist 等），像提交到 GitHub 一样只传源代码与必要文件，减少构建上下文体积与加快构建。

## 方案
- 在仓库根目录添加 `.dockerignore`，只影响 Docker 构建上下文，不影响运行时
- 典型内容（按你的项目结构）：
```
# 通用
.git
.gitignore
.DS_Store
*.log
.vscode/
.idea/

# Node/前端产物（全局匹配）
**/node_modules/
**/.next/
**/dist/
**/coverage/
**/.cache/

# 构建输出与本地临时
**/build/
**/tmp/

# 仅保留依赖清单（不要忽略）
!web/package.json
!web/package-lock.json

# 如果存在额外前端子项目，按需保留它们的 package.json 与 lockfile
#!packages/*/package.json
#!packages/*/package-lock.json
```
- 注意：
  - 不要忽略 `package.json` 与 `package-lock.json`，否则容器内无法正确安装依赖
  - `.dockerignore` 只影响“构建上下文上传”，容器内部依赖仍通过 `npm ci` 或 `npm install` 安装

## 验证
- 执行 `docker build` 前运行：`docker build -f Dockerfile .`（上下文体积会显著降低）
- 在容器内依赖仍会被按固定版本安装（我们已固定 package.json 版本）

## 可选优化
- 如果你希望进一步将 web 构建改为独立阶段，可设多阶段构建，将 `web/` 作为单独 stage 安装与构建，再复制到最终镜像（目前单镜像即可）。

如确认，我将添加 `.dockerignore` 到仓库根目录并写入上述内容。
